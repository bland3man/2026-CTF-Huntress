Challenge

  • Name: 👶 Back in Sixteen
  • Challenge ID: warmups-day-28/mastery
  • Description: “Our sixteen-fingered friend is walking backwards.”
  • Mode: Mastery. The assigned attempt was untimed (deadline: null).
  • Question: For each assigned blob: “Decode the assigned blob completely. What exact answer slug does its final non-empty decoded line instruct you to submit?”
  • Answer format: Three lowercase words separated by hyphens, followed by a hyphen and a two-digit number. Submit only the slug.
  • Answer fields: set1.message through set138.message (one field per blob).

Assigned file

The ZIP contains 138 text files, blob-01.txt through blob-138.txt, one for each answer field. The final message in each blob contains that blob’s unique slug.

Method

The row numbers identify different encodings. Rows 1–11 decode into the opening “Nice work decoding this warmup! To solve,” which confirms that the file is a message assembled from encoded fragments. The useful shortcut is to decode the message tail in rows 16–28: it contains the Game Master instruction and the whole slug, even when the slug starts in a compressed fragment.

RowDecode
16Translate Morse symbols to hex digits, then decode the hex bytes as text.
17Read each a/b group as a five-bit value. Treat each value as one hex nibble, pair adjacent nibbles, then decode the bytes as text.
18Keep the literal text fragment.
19Decode hex bytes as UTF-16 little-endian.
20Decode hex bytes as UTF-16 big-endian and remove its byte-order mark.
21Base64-decode, then decompress gzip.
22Base64-decode, then decompress zlib.
23Decode Adobe ASCII85.
24Expand each count:character, run.
25Convert each U+hhhh code point to its character.
26Execute the Brainfuck program and collect its output.
27Translate Ook! token pairs to Brainfuck, execute, and collect the output.
28Reverse the hex text first, then decode the resulting hex bytes as ASCII.

Joining those decoded fragments reveals the Game Master instruction and slug. For example, blob-01.txt ends with:

t answer to the Game Master: sunny-pillow-laurel-32

For row 28, 2333d2c6 is backwards hex. Reversing it gives 6c2d3332; hex-decoding that gives l-32. It completes the preceding ...laure fragment as ...laurel-32.

Keep the gzip and zlib fragments in the joined text before extracting the slug. In some blobs, the beginning of the slug is in one of those fragments. The script joins rows 16–28 first and then extracts the string matching the answer format. It verifies that every blob produces a slug.

Faster recognition and pitfalls

  • The recurring row numbers make this a batch decoding task. Decode the same row format across every blob with a script instead of solving each file manually.
  • H4sI... is a strong gzip-in-Base64 marker; eN... commonly marks zlib data in Base64.
  • A run of U+ values is Unicode code-point notation. Ook./Ook?/Ook! pairs identify Ook!, a Brainfuck notation.
  • Row 17’s groups are not decoded as Baconian letters here: each group supplies a hex nibble, and pairs of nibbles form text bytes.
  • Do not read row 28 as ordinary hex-decoded text. Reverse the hex characters before decoding.
  • Do not extract the slug from row 23 alone. A slug may begin in row 21 or 22.
  • Keep the answer field IDs exact: blob 1 goes to set1.message, and blob 138 goes to set138.message.
