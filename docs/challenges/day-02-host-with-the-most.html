Triage

  • file / 7z l -slt -> AES-256 encrypted zip. unzip (Info-ZIP) cannot do AES; used 7z.
  • Theme "Host With the Most" + malware-sample packaging -> tried the malware-zip convention password **infected** first. Hit immediately (7z t -pinfected -> Everything is Ok).
  • 12 fixtures: filenames map to ATT&CK tactics/host behaviors (resource/collection/impact samples; host-context, memory-stage, embedded/remote-write, local-dispatch, staged/relay- handoff, outbound-transfer). Each .js is lightly obfuscated; each decodes to a JSON config with steps, an adapter (COM object or LOLBIN), values.campaign_id, and stageCount.

Investigation

  1. Crack the archive. AES-256; password infected: 7z x -pinfected host_with_the_most.zip -oextracted.
  2. Deobfuscate without executing the droppers. Each .js has a pure recover_*() data transform feeding an inspect_*() that eval()s the resulting JSON. local-dispatch.js (reference kept as plain text; not an eligible file type) also defines huntress_lab_*() which uses ActiveXObject("Scripting.FileSystemObject") / WScript.Shell.Run (reference kept as plain text; not an eligible file type) - a real exec sink that was never called. Five distinct obfuscation families were recovered:
    • single-byte XOR (embedded-write key 0x9E, outbound-transfer key 0x2B over :-hex)
    • XOR with a 5-byte key (host-context [30,242,44,59,191], staged-handoff [230,133,19,195,108] over base64)
    • array reverse (remote-write over --decimal; memory-stage base64 -> reverse -> XOR 0x63)
    • base64 identity (relay-handoff)
    • %xx URL-encode identity (impact-plan); raw char-codes (local-dispatch)

Flag Recovery

The field answers are computed live in the Homebase VM from the attempt's own artifact:

  1. 7z x -pinfected <assigned>.zip -oextracted
  2. node scripts/solve_host.js extracted - sandboxes ActiveXObject/WScript (throw), calls only each fixture's inspect_*, base64-decodes each .ps1 FromBase64String() literal, and prints every decoded field.
  3. Map each decoded field to the GM answer_id schema and submit; the GM scores partial credit per field and returns per-field feedback to correct any misses, then re-submit.

Verification (offline, this public copy): the Node solver independently reproduces the hand-decode of all 12 fixtures (a second engine cross-checking the Python decode). Status: method EVIDENCE_VALIDATED; submitted in-VM via Luna. See LUNA_HANDOFF.md and ../Day 02/VM_RunSheet.md.

Lessons Learned

  • **infected is the first password to try** on any AES/ZIP malware-sample challenge - instant hit.
  • Deobfuscate, don't detonate: JScript "fixtures" split a pure recover_*() transform from an inspect_*()/huntress_lab_*() exec sink. Running the config recovery in a vm context with ActiveXObject/WScript stubbed to throw gives the data with zero risk of the FSO/Shell.Run sink.
  • Decode everything; don't over-read the title. "Host With the Most" looked like "pick the host with the most stages," but the GM actually scored ~87 decoded fields with partial credit. Dumping every field (not selecting one property) was the correct hedge and matched the real task directly.
  • Day-02 Arena answers are derived + dynamic. A static file with no embedded flag{}/token is a method-prep sample; the real answers are a function of the per-attempt bytes read in-VM - never hard-code (Time Trial re-randomizes encodings, which expired the first timed run until the parser was generalized).
  • A second engine is cheap verification: decoding by hand (Python) and again via the Node solver cross-checks the method before the timed in-VM run.
