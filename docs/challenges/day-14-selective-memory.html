The challenge

GM prompt: "Objective-C never forgets: every class, every selector, every string is registered and waiting. Read the persistence descriptor and learn what this binary remembers."

This is the same cumulative multi-field forensic inventory the lane has asked every day since Day 1. The evidence zip bundles one specimen per earlier day (d01 .. d14) and asks the same ~17 answer shapes over each: ELF/PE header facts, container and architecture labels, section and symbol tables, a recover_code disassembly, JAR compression methods, .NET metadata version, and the embedded single-byte-XOR HCFG config record.

Day 14's new layer is the toolchain only: an Objective-C (GNUstep / libobjc2 runtime, GNU gold linker) native x86-64 ELF.

Day 14 member

d14--variant-000.elf (challenge artifact, not published), 17,304 bytes, \x7fELF ELF64 LSB, 38 sections. The Objective-C runtime registration tables the prompt alludes to are plain ELF sections, GNUstep-style (not the Apple __objc_classlist / __objc_methname Mach-O spelling, which is why an Apple-flavoured grep finds nothing here):

__objc_selectors  __objc_class_refs  __objc_classes  __objc_constant_string
__objc_cats  __objc_protocols  __objc_protocol_refs  __objc_class_aliases

Symbols confirm one user class and its registered selectors:

  • class: _OBJC_CLASS_TriggerDescriptor (+ _OBJC_METACLASS_, _OBJC_INIT_CLASS_, _OBJC_REF_CLASS_), base NSObject
  • ivar: __objc_ivar_offset_TriggerDescriptor._triggerName.
  • selectors: triggerName, initWithTrigger:, eventCountForModel: (typed _i24), plus runtime alloc, copy, init
  • constant string: objc_str_UserLogin (an NSConstantString in __objc_constant_string)
  • runtime glue: objc_init, objc_ctor, objcv2_load_function, __objc_load, objc_msgSend, objc_autoreleasePoolPush

The persistence descriptor (.hcfg)

Unchanged family mechanic: a .hcfg section holding HCFG + version byte + XOR key + CRC32, then a single-byte-XOR JSON blob.

  • section .hcfg, record at file offset 4000
  • header: 48 43 46 47 01 (version 1) a1 (XOR key 0xa1) 6f 01 da 91 f4 79 (crc32 LE = 0x79f491da)

Reusable notes

  • GNUstep Objective-C on Linux registers via __objc_selectors / __objc_classes / __objc_constant_string sections and objcv2_load_function; Apple section names (__objc_methname, _OBJC_CLASS_$_) do not appear - classify by the GNUstep spelling when the container is ELF.
  • The .hcfg XOR key is in the record header byte 5 (here 0xa1); it does not need guessing, and the CRC32 at bytes 8..11 is little-endian.
  • Grader label conventions held again: elf, x86-64, lowercase 0x hex, true / false as strings, base-10 integers.
