Socket to Me (Day 27, Web Exploitation)

Challenge prompt: "The chat upgraded to websockets and left its manners at the HTTP door. Ride the upgrade into an event stream that was never meant for you."

Flag: Tokenc42fe3b905cbfe7158d4dc7c8284ba48

Single Solve

Target: https://<host>/ (Koa app "Live Case Wire", role=analyst).

  1. GET /api/clues -> {"framework":"Koa","feature_route":"/dispatch-53decf","current_role":"analyst","stream_reference":13777}.
  2. Direct HTTP GET on /dispatch-53decf returns 426 Upgrade Required (WS endpoint).
  3. Plain WS handshake returns 403 Forbidden; the WS auth check reads a query parameter.
  4. wss://<host>/dispatch-53decf?stream=13777 connects and the server immediately pushes: {"ok":true,"effect":"unauthorized_event_stream","evidence":"proof_8f935291d06a4b28ba62ea309ccabe0e"}

The HTTP route is role-gated; the WebSocket upgrade accepts anyone who supplies the integer stream_reference from /api/clues.

Submit: proof-1 = proof_8f935291d06a4b28ba62ea309ccabe0e.

Lessons / changes to the battery

  • New technique: _tech_socket_to_me. Reads /api/clues, opens WSS to feature_route?stream=<stream_reference> with matching Origin header, scans first frame for proof_HEX.
  • New technique: _tech_session_idor_cookiejar. The baseline _tech_session_idor goes through web_scope.registered_get, which does not persist cookies across requests, so an implicit session cookie set on / is lost before the /api/events call. The bespoke technique uses a plain urllib HTTPCookieProcessor opener so the case_session cookie flows into every subsequent GET. It also tries /api/tickets, /api/cases, /api/records, /tickets, /cases for the detail route.
  • The all-or-HELD gate in _lfi_handler zeros a partial batch on a ranked timed mode; a missing extractor for one of five targets costs the whole variant. Build every target class into the battery BEFORE autosolve opens the window.
