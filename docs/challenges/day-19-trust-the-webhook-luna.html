Trust the Webhook

Lane: Web Exploitation Game Master ID: web-exploitation-day-19-trust-the-webhook Modes: Single Solve, Time Trial, Mastery

Core solve

The app treated an event sent to its webhook route as trusted. Start with the Game Master assigned target, load its home page to establish the session, then read /api/clues. The clues provide the current attempt's feature_route, event_type, owner_scope, and role. Send a JSON event to that disclosed route, filling its event and trust fields from those clues. The response's evidence field contains the exact proof_<32 hex> to submit.

The working payload includes redundant event aliases and trust assertions. The successful run did not isolate which individual field the app relied on, so preserve the known payload shape while deriving the route and values anew from each assigned target. Never reuse an old proof, route, scope, or event value.

Mastery target families

Mastery can mix several unrelated web apps in one bundle. The completed bundle used four different techniques:

  1. robots.txt (not found in any source) disclosed an archive directory. Querying its listing with the observed file selector exposed a linked backup containing the proof.
  2. A history event marked a case reference_only; fetching that case through the corresponding API returned its proof.
  3. A search form accepted a boolean tautology and returned a restricted record.
  4. The webhook target exposed its route and event details through /api/clues, then returned proof evidence after the forged event.

The solver classifies targets independently and maps each result to the Game-Master-provided question whose artifact field names that target. It submits only exact proof strings recovered from target responses. The previous Single Solve, Time Trial, and Mastery runs completed successfully.

Time Trial and Mastery request ranked timed attempts by default. Use --practice for untimed practice, or omit it only when you intend to start the timed attempt. The runner uses the Homebase Game Master proxy, waits on the same attempt while targets prepare, and refuses --retry-expired unless the Game Master status says the attempt is expired.

Scope and evidence handling

The client uses only target URLs assigned by the Game Master, keeps cookies in memory, refuses routes outside the target origin, and does not follow redirects. Unknown target families remain unsubmitted for manual investigation. No proof values or session cookies are stored in this writeup.
