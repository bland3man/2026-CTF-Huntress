Why the banked decoder missed them

Every earlier fixture carries its descriptor on the marker line itself - HUNTRESS_ANALYSIS_V1:<KIND>-<payload> (kinds B64, HEX, FRAG, HB64; 13 files each today). The .gs files carry a bare kind token with no payload:

// HUNTRESS_ANALYSIS_V1:SPLIT
const HUNTRESS_ANALYSIS_V1_SPLIT_22eaee83 = [
    "FRAG-763d337c6c616e6775616765.3d676f6f676c655f61707073.5f7363726",
    "970747c726f6c65.3d646f776e6c6f616465727c.766572646963743d7375737",
    ...
].join("");

MARK = HUNTRESS_ANALYSIS_V1:([A-Z0-9]+)-(...) requires the - after the kind, so desc_of() returned None, None and all 55 ids stayed unresolved. Nothing was submitted - the gate held the Single rather than guessing (and therefore no timed variant was spent).

The payload is fragmented twice over: split across array elements and dot-separated inside the hex, exactly the FRAG idiom. Each file carries two copies - the FRAG- prefixed one in the module-level array and a bare-hex copy in encoded_<id> inside buildAnalysisPlan_<id>().

The fix (one extension, spine untouched)

challenges/_lib/solve_poly_d8.py:

  • MARK_KIND = HUNTRESS_ANALYSIS_V1[:_]([A-Z0-9]+) - accept a marker that is only a kind token.
  • split_candidates(s) - rebuild every array-of-strings literal in the source using its own .join("<sep>") separator (default ""), drop arrays under 2 elements / 16 chars, and offer each result twice: once with a leading inner <KIND>- stripped, once whole.
  • desc_of() now carries (kind, payload) pairs through its candidate list so a per-candidate inner kind (FRAG here) can override the file-level one (SPLIT), and still keeps the existing "most complete descriptor wins" rule - so the truncated/partial copy can never beat the whole one.

This is carrier-shaped, not .gs-shaped: any language that fragments the payload into a joined array literal decodes now.

Lesson for the lane

The daily twist can be a carrier shape rather than a language: the marker line may degrade to a bare kind token with the payload reassembled by the fixture's own code ([...].join("")). Match the kind token first and treat any self-joining literal in the file as a payload candidate, letting an inner <KIND>- prefix pick the codec.
