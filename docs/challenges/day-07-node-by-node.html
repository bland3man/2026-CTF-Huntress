What it was

AES zip (pw infected) of 61 inert fixtures across 7 languages: PowerShell .ps1, JScript .js, Batch .cmd/.bat, VBScript .vbs, Python carriers .py, Bash .sh, and the NEW **Node.js .mjs**. 469 per-field questions (938 in Mastery = 2 sets). Nothing is ever executed - every fixture is decoded statically. Each file carries an encoded descriptor that decodes to a v=1|key=value|... string; the answers (role, MITRE technique, adapter, campaign id, url/path/mutex/..., steps, stage count, syntax style, control/expansion form, etc.) are read from those bytes.

Solver

scripts/solve_node_by_node.py (reusable copy in _lib/) + new _lib/decode_node.py.

  • Extends the Day06 unified solver (ps1/js/bat/vbs/py/sh) with an .mjs branch and advanced-bash feature/primitive handling.
  • decode_node.robust_decode() is content-driven: it builds every plausible byte interpretation of the material (raw string, string-reversed, JSON array as hex AND decimal, \xHH, \uXXXX, base64, hex, decimal list) and runs the declared transform + a full brute (xor/add/sub/rolling/repeating/reverse) against each, validating that the result starts v=1|. This absorbs per-attempt codec mutations with no hand-derivation.
  • Mastery delivers ONE outer zip containing inner AES zips evidence-01.zip (challenge artifact, not published)/evidence-02.zip (challenge artifact, not published) (one per set); run_gm detects nested .zip members and maps them to set1/set2.

GM submission mechanics (learned here)

A batch submit is all-or-nothing (returns incorrect and banks nothing if any field is wrong). But individual submits BANK cumulatively within an attempt (remaining counts down, accepted_ids accumulate). The timed solver therefore tries the full batch first and, if not CORRECT, falls back to a grouped submit (confident byte-derived fields, then each model-label class) dropping to per-field only where a class isn't wholly accepted - so one wrong label never sinks the attempt.
