The challenge

GM prompt:

The source code says where it would fetch from, and the generated network evidence says where the requests actually went. Reconcile both into one download graph, and find the indicator that shows up on only one side of the story.

Artifact: artifact_0.bin (challenge artifact, not published), a 114808-byte AES-encrypted ZIP (password infected), 127 inert script members - 22 .sh, 14 .py, 12 .js, 10 .vbs, 9 .php, 8 .mjs, 5 each of .cmd/.lua/.pl/.rb, 4 each of .ps1/.bat/.mof/.ts/.au3/.applescript/.proj/.ahk.

Field counts: Single and Time Trial 1139 fields each; Mastery 5695 fields (5 independent sets of 1139, set1. ... set5. prefixes, each set its own re-randomized member zip).

The "network evidence" framing is flavour: there is no pcap or log member. Every fixture is self-describing - the descriptor inside each file is both the source-side intent and the recorded-side result, so "reconciling both sides" is exactly decoding the Material_<id>/Codec_<id> pair and reading the steps/stage_profile/url keys out of the recovered descriptor. The "indicator on only one side" is the per-fixture URL/campaign/mutex/wallet value that appears only in the decoded descriptor and never in the plaintext of the carrier.

How it was solved

No new reversing was needed. The banked lane spine (challenges/_lib/autosolve_script.py, driven by challenges/_lib/autosolve.py) handled the whole thing:

  1. ctf_gm.unzip (reference kept as plain text; not an eligible file type) opens the AES zip with password infected; Mastery's outer zip is split into its five per-set member zips by autosolve_script._set_blobs.
  2. Each member is decoded via the Day 7 structured extractor, falling back to the generic Material_/Codec_ path (generic_decode) and then to solve_poly_d8.extra_answers for the PHP / host-container v=3 descriptors and the advanced-bash fixtures. 52 members fall through the primary extractor (AppleScript, AutoIt, AutoHotKey, Lua, Perl, Ruby, HTA/WSF/SCT hosts) and are answered by the generic/poly paths - they are "undecodable" only to the first extractor, not to the solver.
  3. field_formats.confirm_all banked 44 new tokens on the Single and 5695 on Mastery, so each later mode started with today's formats already confirmed.

Offline replay reproduces the GM result exactly: 1139/1139 resolved, 0 unresolved (scripts/replay_single_offline.py -> scripts/single_answers.json).

Today's new layer

The novelty keys were a new polyglot carrier family: **AutoHotKey (.ahk)**, 44 fields across four fixtures (benign-utility, downloader, launcher, staged-chain). It is a carrier, not new knowledge - the descriptor keys are unchanged, so the generic path answered all 44 with no code change. This confirms the standing hypothesis (now n=6) that a self-describing new carrier costs nothing while the descriptor schema holds.

Takeaways

  • Flavour text can describe two sides of a story that are physically one artifact. Do not go looking for a pcap that the digest's member list does not contain; the descriptor carries both halves.
  • A new polyglot carrier (AutoHotKey) with the unchanged descriptor schema needs zero code. Recognize, reuse, do not rebuild.
  • When a GM question explicitly redirects the technique mapping ("treat X as the central behavior rather than Y"), that sentence is the specification. collection-attack = T1555.003 (reference kept as plain text; not an eligible file type).
