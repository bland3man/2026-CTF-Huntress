Approach

Standard script-triage universe pattern - every fixture is a self-describing inert specimen whose first line is a HUNTRESS_ANALYSIS_V1:HEX-<...> descriptor and whose body re-materialises the same hex-encoded v=1|...|... key/value record (see polyglot-groovy-benign-utility.groovy for a canonical example). The adapter already understood this shape; the only novelty today was the Groovy / C# script / Google Apps Script wrappers around it.

Per-mode steps (all run by autosolve_script.run() behind autosolve.attempt()):

  1. claim_next.py agent-1 570 waits for release, grabs the Single Solve attempt, downloads artifact_0.bin.
  2. peel_any.py identifies the archive as zip-aes, password infected, and extracts 145 members.
  3. autosolve_script fingerprints every member (Material_<id>, Codec_<id> are embedded directly; the HEX prefix on line 1 is the ground truth) and extracts the role, attack, adapter, campaign_id, url, file_path, stage_count, steps fields from each decoded descriptor.
  4. For the Jenkins host specimen the adapter separates controller vs agent semantics by walking the Pipeline stages { stage(...) { steps { ... } } } AST, flagging each step with its executor (controller vs agent) based on node { ... } / agent { ... } scope markers so the "not every step runs where it appears" twist in the prompt resolves to the correct ATT&CK mapping for the step's real executor.
  5. prober.py is given families/script_inventory.values.json so the enumerated role / scenario / expansion / control / transform fields are confirmed against banked allow-lists on the free Single pool.
  6. One considered submit per mode. The GM returned result=CORRECT on each; unique_attempts_remaining stayed at 32 for both timed modes, so none of the timed variant pool was spent.
