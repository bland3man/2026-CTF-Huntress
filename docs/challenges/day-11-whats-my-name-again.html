Whats My Name Again? (Day 11, metadata-forensics)

Summary

Filenames on disk are randomized; the organiser's own prompt is explicit that the recovery comes from the Windows PE VERSION_INFO resource instead. This attempt's delivery is one PE file, on disk as telemetry-agent-001.exe (challenge artifact, not published), whose embedded VS_VERSION_INFO -> StringFileInfo -> OriginalFilename field reads pe-base-386.exe (challenge artifact, not published) - the impersonator the prompt asks to expose: the file calling itself telemetry-agent-001.exe (challenge artifact, not published) on disk is, by its own internal record, pe-base-386.exe (challenge artifact, not published).

Gap found and fixed same day

autosolve_metadata.py (not found in any source) had no handler for the pe.version_original_filename field token; the first autosolve attempt raised ValueError: unknown structured field 'pe.version_original_filename'. A new extractor, challenges/_lib/pe_version.py, was added and registered in autosolve_metadata.py (not found in any source): it walks the PE resource directory to the VS_VERSION_INFO resource, parses the fixed VS_FIXEDFILEINFO block and the StringFileInfo table, and exposes every standard VERSION_INFO string key (OriginalFilename, InternalName, ProductName, CompanyName, FileDescription, FileVersion, ProductVersion, etc.) under both the exact GM token spelling and the natural synonym spellings a future question could use. The fix cost under a second of agent time; the three modes solved immediately after.

  • This is the reference writeup for any future PE identity-recovery / impersonation-style challenge.
