Percent Chance

Warmups SSTTMM Modes reported CORRECT in this write-up

Challenge

Category: warmups (lane warmups, GM id warmups-day-07). Day 07.

Artifacts

A single text blob delivered by the GM for the attempt (mastery_blob.bin (challenge artifact, not published) saved locally for the Mastery delivery; Single Solve/Time Trial blobs are read directly from the GM response, not saved separately).

Investigation

Reconstructed from the saved solver (scripts/solve.py) - the title is the pun: "Percent" = URL/percent-encoding (%xx escapes), which is the actual transform being undone:

  • The blob is percent-encoded text (urllib.parse.unquote-decodable).
  • The solver applies urllib.parse.unquote in a loop (up to 5 times) until the text stops changing - i.e. it keeps un-escaping layers of percent-encoding until it reaches plain text, the same "peel until stable" pattern used for Day 06's octal-encoded "Eight Is Enough" and Day 07's own "Seven-Zip" sibling.
  • The final decoded text is split into non-empty lines; the last line is searched for a slug pattern word-word-word-NN (three lowercase hyphenated words followed by a two-digit number).
  • That matched slug is submitted verbatim as the answer for every answer_id.

Flag Recovery

The answer is the three-word-plus-number slug recovered by the regex above, after however many percent-decode passes were needed to reach it (the loop handles a variable number of nested encoding layers per attempt).

Minimal Reproduction

python3 scripts/solve.py

Uses challenges/_lib/ctf_gm.py's GM()/solve_mode() to handle the GM round-trip and prints the result.

Lessons Learned

  • "Percent" in the title is a direct hint at percent-encoding - the same "decode this encoding until it stabilizes, then pull a slug from the last line" shape recurred across several Day 06/07 warmups with different base encodings (octal, percent-encoding) wrapping the same slug-extraction tail.
