Disk layout findings

Single Solve

mmls identified a valid GPT at 512 bytes per sector. The partition entry has start LBA 34, end LBA 222, length 189 sectors, and name HUNTRESS EVIDENCE. Therefore the submitted sequence is the compact JSON array [34].

The evidence partition begins at byte offset 34 × 512 = 17,408. Its extent is 189 × 512 = 96,768 bytes, ending at byte offset 114,176 (exclusive). The protective MBR is at LBA 0, the primary GPT header at LBA 1, and the partition-entry array occupies LBAs 2–33. A backup EFI PART GPT header is present at the final LBA, 255.

Time Trial

The disk image in evidence.zip (challenge artifact, not published) has three GPT partitions. Their starts in table order are 273, 285, 400, submitted as [273,285,400]. Their corresponding byte offsets are 139,776, 145,920, and 204,800.

Method

1. Retrieve assigned bytes and verify them

The supported proxy was used for every Game Master request. For example:

curl -sS 'http://[ip]/huntress-ctf-proxy?op=artifact&challenge=metadata-forensics-day-28-where-it-all-began' \
  -o metadata-day-28-evidence.zip
sha256sum metadata-day-28-evidence.zip
unzip -l metadata-day-28-evidence.zip
unzip -p metadata-day-28-evidence.zip disk-001.img > disk-001.img
python3 [local path] disk-001.img

For Time Trial and Mastery, change the challenge= value to the exact mode ID from the Game Master start response. The bytes were not retyped or fetched from another identity.

2. Parse structures from raw bytes

  • mmls reports partition starts in sectors and labels GPT metadata separately from actual partitions. disk_layout.py (not found in any source) filters partition rows and emits compact JSON.
  • Python's zipfile, hashlib, struct, xml.etree (reference kept as plain text; not an eligible file type), and email/text parsing handle nested ZIP names, full-file hashes, JPEG/PNG/PDF headers, PE fields, .NET MVID, MSI ProductCode, OOXML external targets, SQLite page size, EVTX records, registry root name, Prefetch name, PCAP records, and Mach-O universal-binary CPU types.
  • Media codec names follow the artifact codec identifier (flac, opus, mp3, aac, or FFmpeg-style PCM names). MP4 dimensions come from the video sample-entry header.
  • ZIP member names, external OOXML targets, and Mach-O CPU-type sets are sorted for their canonical answer arrays. Partition starts remain in partition-table order.
  • Full-file digests include the exact BOM and bytes. A SQLite header page-size value of 1 means 65,536 bytes by the SQLite format.

The reusable parser is solve_mastery.py (not found in any source). It derives all 396 answers from the downloaded outer ZIP and the saved API response. solve_bundle.py (not found in any source) uses the same parsers for a one-bundle mode such as Time Trial. The generated requests are kept under mastery-results/ and time-trial-answers.json (not found in any source).

3. Submit using exact answer IDs

All values were sent under questions[].id from the live response. JSON-array answers were compact JSON strings without Markdown or prose. The 396-answer Mastery payload was 30,493 bytes, below the Game Master's 4 MiB request limit.

submit_mastery.py (not found in any source) submits one combined batch first. If the service returns incorrect, it recursively divides only the rejected batch, records accepted subsets, and logs each response. This isolated two generator mistakes shared by all 12 sets: the PE original-filename field was initially confused with the challenge artifact filename, and the SQLite page-size suffix was initially confused with a file-size question. The parser was corrected to read the PE version resource value and SQLite header. All 372 other values were accepted on the first verification pass; the 24 corrected values were then accepted together, completing Mastery.

The final successful result responses were CORRECT; no timer was running in these starts because run_for_time was false and the API deadline was null.

Faster workflow next time

  1. Save the complete start response immediately; it contains the exact IDs, questions, syntax, and artifact capability.
  2. Fetch the artifact once through ?op=artifact, save to disk, and verify the API SHA-256 before extraction.
  3. Keep nested bundles in memory or separate folders, and map each question's artifact reference to the matching basename. Never mix bytes from separate variants.
  4. Run solve_bundle.py (not found in any source) for one bundle or solve_mastery.py (not found in any source) for all 12. Check that the output answer count equals the API count before submitting.
  5. Submit all answers together while the JSON body is below 4 MiB. If rejected, use submit_mastery.py (not found in any source) to bisect rejected groups; fix a field parser, regenerate the answer file, and send only unresolved IDs.
  6. For disk questions, use mmls first, then multiply each start LBA by 512 to inspect the partition at its byte offset. Keep LBA sequences in table order and keep set-valued metadata arrays in their canonical sorted order.
