Shape

Single Solve + Time Trial (one shape)

Single target with:

  • / → "Header House · Micronaut" link to /api/clues
  • GET /api/clues → {"framework":"Micronaut","feature_route":"/<slug>","current_role":"analyst","deployment":"trusted_reverse_proxy"}
  • GET <feature_route> with no header → {"error":"loopback_only","evaluated_client":"[ip]"} (external client IP from the reverse proxy)

Micronaut's app logic uses the first value of the X-Forwarded-For chain as the trusted client address; the proxy does not strip client-sent XFF before forwarding.

Exploit: GET <feature_route> with header X-Forwarded-For: 127.0.0.1 → {"ok":true,"effect":"proxy_trust_admin_bypass","evaluated_client":"127.0.0.1","evidence":"proof_<32hex>"}

Submit proof-1 = proof_<32hex>.

Gotchas

  • Mastery is a lane sampler, not variants of the Single. Every target must be recognized fresh.
  • The LFI prefix in Target 4 is /var/www/html/pages/ so /etc/passwd wants ../../../../etc/passwd (not fewer ..): fewer segments produce pages/../etc/passwd which does not exist.
  • Earlier variant lost: the autosolve started a Mastery attempt before any lane solver existed for the non-Micronaut targets; its deadline expired before I could write the extra extractors. The second attempt (no server deadline) was solved by the parallel 5-target probe.
  • _list_snapshot.json had aged past the MAX_AGE_S=600s window during repair; the solver's NO-LIST-FALLBACK path then thought every mode was solved. Fix: rewrite the snapshot via list_snapshot.write(stage, 27, gm.list(day=27)) before rerunning autosolve.
