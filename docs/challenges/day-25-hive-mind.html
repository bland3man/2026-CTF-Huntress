Day 25 - Hive Mind (metadata-forensics)

Prompt: registry hives from multiple systems were renamed; identify each true root, regroup the systems, isolate the planted hive.

Result

  • Single Solve: CORRECT - flag Tokendab60d0deb4e15f8b2d44d78ddf46fd3
  • Time Trial: CORRECT (ranked) - flag Token147253c3207958e3b1780d2c58fd2ae6
  • Mastery: CORRECT (ranked) - flag Token64978bc7d92e23305c88fc8d2153e0d7

Single: registry.hive_root_name

Artifact: zip with hive-001.hiv (regf, 8192 bytes). The first autosolve answered via the alias registry.hive_name, which reads the regf header file-name field (0x30..0x70). That field is a truncated path tail ("ress-artifact-assembly-line.hiv"), so the GM rejected it. The "true root" is the name of the root nk cell: root cell offset at header +0x24, cell at 0x1000+offset, name length at nk+0x48, name at nk+0x4c (flags 0x20 = ASCII). Value: HuntressArtifactAssemblyLine. Added a registry.hive_root_name extractor (aliases registry.root_key_name, registry.root_name) in challenges/_lib/autosolve_metadata.py.

Time Trial

Same shape as the Single plus the cumulative catalog; the new extractor answered the hive field and the existing spine did the rest.

Mastery: evidence-note-copy-filename

Residue was set1/set4 evidence-note-copy-filename. The old Day 17 rule looked for a member named exactly evidence-note.txt. Today the originals are evidence-note-<hex>.txt and the renamed copy is evidence-note-copy-<hex>.txt (identical bytes). Added a fallback: among evidence-note* members, find the identical-bytes pair and return the one with "copy" in its name.

Lessons

  • A header "name" field is not the root key name; read the root nk cell.
  • Day 17 copy-filename rule assumed a fixed original name; match by identical bytes instead.
