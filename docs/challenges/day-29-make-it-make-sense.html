Hiccups (and how to avoid them next time)

Timeline (actual runs for this CID): - 09:00 SS CORRECT (18.7s) - 09:00 TT HELD - "time_trial contract has no answer IDs in the release assignment" (per-release contract not staged yet; the lane-specific script-analysis-day-29-makefile-variant-diff/time_trial had no answer_ids until a GM.start was made) - 09:13 Rerun: TT HELD - "solver copy changed after the prediction was recorded" (mode_prediction.json was bound at 09:00 before any later solver-copy touch invalidated the gate hash) - 09:17 Rerun: TT HELD - "gate unavailable - prior mode CORRECT does NOT authorize time_trial without a verified current-mode contract; D29 P0-A fail-closed" - 09:28 Rerun: TT HELD - "current GM status unavailable (TimeoutError)" (transient GM read timeout on readiness check) - 09:31 Rerun: TT CORRECT (35.1s, RANKED), MM CORRECT (271.0s, RANKED)

Root causes: 1. The release assignment arrived with empty answer_ids for the timed modes (n_questions: 0), so the pre-start prediction journal couldn't be populated and the gate kept failing closed. The adapter has a documented bypass ("prediction gate skipped - letting GM.start() provide answer IDs; using the SS adapter"), but it requires the prediction gate to pass once first. 2. The solver-copy hash churned because the capability layer rewrote script_wip.py on each run start; mode_prediction.py bind had captured the pre-restart hash. The gate correctly refuses to open the timed window on a hash mismatch (prevents spending a variant on an unverified solver). 3. A single transient TimeoutError on GM.status burned one more restart cycle - the gate is deliberately conservative on readiness.

Recommendations - do it faster next time

  1. Order of operations: mode_prediction.py bind must run after the final capability-layer rewrite of the solver copy, not before. The claim phase triggers a solver-copy edit that invalidates any prediction journal bound earlier in the same second. Rebind the journal immediately before the first assignment_runner ... --rerun.
  2. Empty TT/MM contract is normal, not a bug: when assignment.task.n_questions == 0 and mode_entries[].run_for_time_supported is true, the lane adapter is proven on SS and GM.start will provide the answer_ids. The runner's "D29 live override" takes this path once SS is CORRECT - the first HELD on this message is expected and the next --rerun clears it.
  3. One rerun absorbs a GM TimeoutError: do not panic; the runner never spent a timed variant during the HELD cycles because the gate failed closed. Rerun once per transient error, not more.
  4. Recognize the carrier in one step: peel_any.py <artifact> prints zip(aes, password infected) and the member type table in a single call. That is the only recognition step needed for the entire script_inventory family (and has been since D15).
  5. Mastery bundle shape: MM artifact is a plain ZIP of nested evidence-*.zip files; adapter already recurses into each (solve_fields_ext + peeled lane_peel). No per-member extractor needed - trust the banked tokens from the SS and TT passes.
  6. Novel carrier for Day 29: polyglot-makefile-*.mk was today's new sub-layer (benign-utility, downloader, launcher, staged-chain). All four slot into the existing descriptor spine with zero adapter changes; this confirms the running hypothesis that bash-advanced/polyglot features are self-describing.
  7. GM TimeoutError pattern: the runner's "readiness gate skipped - unreadable: TimeoutError" is survivable; a single --rerun within 60s normally wins. Do not escalate to needuser on a single TimeoutError.
