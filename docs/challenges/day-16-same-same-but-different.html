Challenge

GM prompt: "Several obfuscation families have scrambled the same logic independently, or so they claim. Strip each version down to its semantics, prove which ones are truly equivalent, and expose the variant that quietly changed the plot."

Artifact: artifact_0.bin (challenge artifact, not published), 113162 bytes, WinZip-AES zip (123 members, password infected) - 22 .sh, 14 .py, 12 .js, 10 .vbs, 9 .php, 8 .mjs, 5 .cmd, 5 .lua, 5 .pl, 5 .rb, 4 .ps1, 4 .bat, 4 .mof, 4 .ts, 4 .au3, 4 .applescript, 4 .proj. Every fixture is inert; nothing was executed.

The "equivalence" framing is prompt-level only. Underneath it is the same per-field script-triage inventory the lane has answered since Day 1: each fixture carries its own self-describing descriptor (Material_<id> / Codec_<id> plus load/decode/recover/inspect/plan_<id>), and the semantics the prompt asks you to "strip down to" are exactly the descriptor's steps graph, stage-count, role and ATT&CK mapping. Two fixtures that decode to the same ordered behavior graph are the equivalent ones; the "variant that quietly changed the plot" is the fixture whose decoded graph has a different terminal step (e.g. dispatch_process where its siblings end in return_configuration), which the descriptor states plainly once decoded. No semantic diffing of obfuscated source was needed - the graph is in the bytes.

Method

  1. claim_next.py claimed the challenge and ran the banked lane adapter challenges/_lib/autosolve_script.py before any hand analysis.
  2. The adapter peeled the AES zip (pyzipper, password infected), walked all 123 members, decoded each carrier (base64 / hex / fragmented hex / gzip / XOR / char-code arrays) and read the descriptor out of each fixture.
  3. Field answers came straight from the decoded descriptors - scenario/role enums, ATT&CK ids, campaign ids, urls, wallet, mutex, file paths, JScript function/invocation/property style, Batch expansion + control form, VBScript transform + control form, stage counts and >-joined step graphs.
  4. One considered submit per mode under the exact answer ids. field_formats.confirm_all banked 56 new tokens at Single and 1094 more at Time Trial.
  5. Time Trial and Mastery were opened only by AUTOSOLVE after its readiness gate ("prior mode already CORRECT live on this challenge"), never by hand.

Why no adapter extension was needed

autosolve_script.py already generalises over carrier x transform x representation (the universe test is 1445/1445 PASS). Ruby's carrier idioms ("...".unpack, hex string literals, base64 via Base64.decode64, fragmented hex concatenation) all fall inside the existing codec table, and the descriptor key names are unchanged, so the new fixtures resolved on the first pass - Single Solve landed in 5.7 s with 1095/1095 accepted. The theme ("prove which are equivalent") added no new field shape.

Takeaways

  • A new language in this lane is now routinely free: the adapter reads the descriptor, and the only genuinely new knowledge is the interpreter -> ATT&CK mapping. For Ruby that is the parent T1059 (no sub-technique exists).
  • A prompt that sounds like a new analysis task ("prove equivalence", "find the divergent variant") can still be the same inventory underneath - check the answer-id diff before believing the framing.
  • 69 new keys, 0 removed: the Day-8-onward pattern (one carrier/theme + two bash-advanced features per day) held again, which is why the pre-warmed adapter could finish Single in under 6 seconds.
