Today's new layer (Zig) and the two fields the spine did not yet handle

1. d10_analysis_has_hcfg_section (enum true/false) - NEW field

The Zig d10 ELF carries a named .hcfg PROGBITS section (section [23]) in its section header table holding the single-byte-XOR config record. The spine had no handler for the analysis_has_hcfg_section suffix. Added one: **true iff a named .hcfg section exists in the ELF section header table** (fallback: a successful HCFG header parse for any kind). d10 ELF => true.

2. d10_analysis_machine - INTEGER-kind, and d10 rotates ELF <-> native PE per attempt

The crux of the "cross-platform" theme. d10's delivered binary is mutated per attempt: sometimes an ELF (d10--variant-NNN.elf (challenge artifact, not published), e_machine 0x3e), sometimes a native Windows PE (d10--variant-NNN.exe (challenge artifact, not published), COFF machine 0x8664). The question's own answer_format is kind: integer (base-10), so the grader wants the raw numeric machine id, not a text token:

  • ELF x86-64 => e_machine 0x3e = 62
  • native PE amd64 => COFF machine 0x8664 = 34404

The spine's integer-kind machine handler only covered ELF (the Day 8/9 lesson). For the PE variant it was falling through to the string machine path and emitting x86-64 (and later probe tokens amd64/x86_64/AMD64), all of which the integer grader rejected. Fix: when ikind == "integer" and the file is a PE, return str(pe_machine(main)) (the decimal COFF machine) - the same integer contract the ELF branch already honored.

GM / timed-route gotchas resolved (banked for the team)

  • A timed route can return 409 timed_intent_not_available for the ranked (run_for_time:true) pool while a **plain op=start** on the same route succeeds. Do NOT auto-escalate a plain-start failure to run_for_time.
  • An expired-but-not-yet-retired timed attempt occupies the single timed-intent slot and makes a fresh op=start 409. op=retry both retires it AND provisions a fresh attempt, returning the full start-shaped payload (attempt_id, questions, download, deadline) - use that return directly; calling op=start again would 409 anew. Patched into ctf_gm.GM.start (reference kept as plain text; not an eligible file type).
