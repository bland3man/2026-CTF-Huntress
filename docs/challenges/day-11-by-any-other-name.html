Summary

A name isn't a behavior. The delivery carries 811 answer fields: three named PowerShell samples (resource-sample.ps1 (not found in any source), collection-sample.ps1 (not found in any source), impact-sample.ps1 (not found in any source), one per MITRE tactic category - resource access / collection / impact) asked to name their own scenario + primary ATT&CK technique ID (plus embedded indicators: URL, wallet, mutex, collection file/user-agent, impact extension/note/URL), and a full per-carrier matrix across every interpreter/polyglot/host-wrapper family the script-analysis adapter supports (jscript, vbscript, batch, python in nine packaging forms, bash incl. the bash-advanced-* feature set, nodejs, polyglot-php/lua/typescript/wmi_mof, and the host-wsf/host-hta/host-sct/host-php/host-lua wrapper carriers), each carrier asked for its role/primary-ATT&CK-technique/decoding-adapter/campaign plus format-specific extras (URL, file path, stage count, obfuscation style, host/next-stage, etc.).

No new extractor or decoder was needed. challenges/_lib/autosolve_script.py's banked LANGS carrier table (including the 13 proxy-execution/persistence carrier rows added the night before this release - .url, .rdp, .scr, .cpl, .job, .socket/.path, .rules, .profile, .pth, .psd1/.ps1xml, .scf) and the existing solve_node_by_node family decoders already covered every carrier and role in this delivery. run() derived every one of the 811 fields from the attempt's own bytes in one batch submit.
