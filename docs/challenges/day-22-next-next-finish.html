Each file is an "inert composite-analysis fixture" that embeds a base64-encoded JSON descriptor (keys a..h or role-specific) carrying the sample's observable indicators (URL, wallet, mutex, user-agent, path, campaign, host profile, obfuscation profile, stage profile, next-language). File names encode the sample role (resource = cryptomining, collection = credential staging, impact = ransomware/wiper, plus the polyglot-* and host-* variants for each language).

Solver

The project's banked lane adapter challenges/_lib/autosolve_script.py already covers this family (script_inventory, generic across days). I did not write a per-day solver.

  • Single: ran autosolve_script.py directly on the challenge id - full batch submit answered all 1417 fields and the GM returned CORRECT in 14.7 s. 278 new tokens were banked into field_formats.json.
  • Time Trial and Mastery: ran the dispatcher autosolve.py 22 <id> script-analysis with HUNTRESS_AUTOSOLVE=1 HUNTRESS_GATE=0. The gate override is sanctioned (the only override, documented in the adapter's HELD message); it was justified because:
    • the Single had just been accepted CORRECT with 0 wrong on the live GM in this same run, so the solver is proven for today's variant;
    • the challenge was never staged on this machine (homestation 08:55 task did not fire today - coord watcher was 1016 minutes stale when the Commander opened), so the regular prebuild-and-stage gate had no residue to read.
  • Dispatcher output: time_trial: CORRECT in 14.1s by sudo_who_farted [RANKED], then mastery: CORRECT in 69.2s by sudo_who_farted [RANKED].

What the adapter actually does: solve_node_by_node.analyze/build parses every script's string literals, finds the embedded base64 (or XOR / codec) descriptor, decodes it, maps each descriptor key to the matching answer_ids suffix (role -> scenario, interpreter extension -> MITRE sub-technique, descriptor fields -> url/wallet/mutex/user-agent/path/campaign/host-profile/obfuscation/stage-profile/next-language/stage-count/steps), and emits the full answers dict. The LANGS registry in autosolve_script.py already carries ordered MITRE candidates for carriers that have no single interpreter sub-technique (HTA, WSF, XSL, MSBuild, INF, task XML, systemd, launchd, cron, XDG, WMI MOF, URL/RDP/SCR), so the per-field fallback probes them without ever guessing on the batch.
