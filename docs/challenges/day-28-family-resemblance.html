All three have the same ELF class, little-endian encoding, ET_DYN type, entry point 0x10e0, machine value 62, and section-name sequence. That metadata alone makes the false friend convincing.

The two family specimens have identical .text bytes and their decoded HCFG JSON objects are byte-for-byte equal. Their whole files differ at only one byte (offset 12,824). The false friend has a different .text hash and a separate config:

  • Family config: domain node-000.day28.example.invalid, IPv4 198.51.100.50, mutex Global\HuntressBR28_000, URL https://node-000.day28.example.invalid/api/BR28-000, service HuntressLab-Day28-Family-000.
  • False-friend config: domain decoy-000.day28.example.invalid, IPv4 198.51.100.70, mutex Global\HuntressFF28_000, URL https://decoy-000.day28.example.invalid/api/FF28-000, service HuntressLab-Day28-False-000.

This is why header and filename similarity were treated as weak evidence. Matching behavior and matching decoded configuration identified the family; the changed code section and decoy configuration identified the false friend.

Analysis method

  1. Started each mode through the Game Master proxy and saved the complete start response. Time Trial and Mastery used run_for_time: true.
  2. Downloaded each assigned evidence.zip through ?op=artifact. For Mastery, downloaded all 12 deliveries by delivery index and checked every SHA-256 against the start response before analysis.
  3. Inspected the ZIP central directory and preserved its member order. The bundles use WinZip AES encryption; pyzipper extracted the exact bytes with the lab password infected.
  4. Parsed each format from its bytes:
    • ELF headers, sections, symbol tables, section data, and disassembly. ELF symbol ordering is retained for questions that require symbol-table order.
    • PE/COFF headers, section tables, machine codes, and primary COFF symbols. Long COFF names are resolved through the string table; auxiliary records are skipped.
    • CLR metadata-root and CLI runtime fields for managed PE files.
    • JAR central-directory entries, manifest Main-Class, Java classfile constant pools, method tables, and access flags.
    • WebAssembly magic and section structure where requested.
  5. Decoded HCFG records only after validating them. A record is HCFG, version byte, XOR key byte, little-endian payload length, little-endian CRC32, then XOR-encoded JSON. Base64 carriers were decoded and validated the same way; invalid lookalike records were ignored.
  6. Decoded the packed Day 19 and Day 20 overlays using their documented layouts. Day 19 uses ror8(byte XOR k2, 3) XOR k1 and checks the unpacked SHA-256. Day 20 checks the RS20 bounds and scratch SHA-256 before reading the HCFG resource.
  7. Generated every response from the extracted bytes. JSON-array answers were serialized as compact JSON strings because the submission API requires every answer value to be a string. Each submission used the exact IDs from its start response.

The implementation is in analyze.py. fetch_artifacts.py verifies downloaded delivery hashes; solve_mastery.py prepares the set-prefixed 4,704-field answer map. Dependencies and rerun commands are in README.md.

Additional notes (merged from README.md)

Family Resemblance workbench

This directory contains the saved Game Master assignments, downloaded evidence, answer maps, analysis scripts, and the final write-up.

Reproduce the analysis

From this directory, install the parser dependencies:

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

analyze.py takes an AES-encrypted evidence.zip, extracts its members in central-directory order, validates embedded HCFG records, and writes ss_answers.json. The artifact ZIP uses the lab password infected.

For a saved Single Solve or Time Trial delivery:

FR_WORKDIR="$PWD" .venv/bin/python analyze.py

For the 12-delivery Mastery bundle, download and verify its assigned artifacts with the saved start response:

.venv/bin/python fetch_artifacts.py mastery/ss_start.json mastery \
  --challenge binary-reverse-engineering-day-28-family-clustering/mastery

Then derive the answer map:

.venv/bin/python solve_mastery.py mastery/ss_start.json mastery mastery/derived \
  --challenge binary-reverse-engineering-day-28-family-clustering/mastery

The default writes a reviewable ss_submit.json. Add --submit to send the answer map through the supported Game Master proxy. The saved mastery attempt is already solved, so a repeated submission will not score again.

render_assignments.py rebuilds the complete player-facing assignment briefs from the saved API start and status responses.
