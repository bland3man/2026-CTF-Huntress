Single Solve method

  • Artifact: single_0.bin, 672 bytes, a ZIP (metadata-day-29-evidence.zip) holding one member, certificate-001.pem.
  • Question: d29-x509-001-x509-sha256-fingerprint - "Determine x509.sha256_fingerprint for certificate-001.pem", exact 64-hex, case-insensitive.
  • Recipe: base64-decode the PEM body to DER, SHA-256 the DER bytes, print lowercase hex. The field key is x509.sha256_fingerprint; the shared adapter did not list it in FIELDS but resolved it through the GM-confirmed alias x509.fingerprint_sha256 (kb/field_recipes). The fingerprint is of the certificate DER, not of the PEM text or the zip member.

How Time Trial and Mastery differed

  • Both are cumulative recaps in an evidence.zip (Mastery: 13 sets of ~34 ids, 442 ids in total, bundled in an ~8.7 MB artifact).
  • Time Trial had 34 ids: roster filename, evidence-note size/MD5/SHA-1/SHA-256/magic-16/BOM flag, the Day 4-28 field tokens (jpeg, png, pdf, zip x2, pe x3, dotnet, msi, lnk, ooxml, email, audio, video, elf, macho, apk, jar, sqlite, evtx, registry, prefetch, pcap, disk), the Day 29 x509 fingerprint, and the synthesis question metadata-day-29-synthesis-sha256-order (file names sorted by ascending full-file SHA-256, compact JSON array).
  • Mastery added per-set variants: renamed evidence-note copy filename/size/digests, roster size/digests, and evidence-note filename questions.
  • Recipes per family: digests/size/magic from the member's raw bytes; filenames from the zip listing (roster = the member whose basename starts with roster; renamed copy = the member with identical bytes to the evidence note under another name); format fields via the same autosolve_metadata extractors proven on Day 28 (24/24 offline test); synthesis = sort named files by their SHA-256 hex.
  • Answers were derived from each attempt's own bytes. Single Solve values were never reused.

Structural vs runtime: the offline fixture test is structural; the CORRECT results come from the GM.

LESSONS / RECOMMENDATIONS

  • Missing piece: roster-filename. The adapter's "exact filename" branch already returns the single member of the zip whose basename starts with roster (Day 20 logic). The prebrief gate runs against the Single Solve zip as stand-in; that zip had only certificate-001.pem, and the roster question's artifact is the bare evidence.zip (no -> member). contract_preflight.split_unresolved therefore classed it as "NO extractor" instead of "needs real bytes". It was a gate classification gap, not an extractor gap.
  • Stall: the timed modes were HELD across four rounds (journal missing, contract IDs missing, coverage empty, roster false positive). I cannot give an exact wall-clock figure; the runner log shows the first attempt at 09:00:03 and the pass only after the Commander's fix.
  • What would have been faster:
    1. Bind and fill the prediction journal immediately once Single Solve is CORRECT, instead of waiting for the held message (I only did it after the first HELD).
    2. Have the release assignment carry TT/MM answer ids at stage time; the gate cannot pass without them.
    3. In contract_preflight.split_unresolved, treat role-named members (roster, evidence-note copy, evidence-note) that are absent from the stand-in as needs-real-bytes. This is the shared fix; patching the clone to answer without a roster would fabricate data.
    4. Add x509.sha256_fingerprint to FIELDS directly (it currently resolves through an alias recipe) and a fixture to the lane catalog test.
  • Next-day candidate: the layer sequence suggests the recap bundle keeps growing by one field per day; keep the offline TT-shaped fixture test (certificate + roster + note) as a reusable check.
