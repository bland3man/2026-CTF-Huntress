The actual Day 18 layer

The prompt's call-graph framing is flavour. The real change is in how two long-standing fields are specified: the d02 C++ symbol fields are now stated as an explicit symbol-table traversal, not as a value to find in the bytes. The GM's own question text (from the mastery residue, verbatim):

Use all d02-- members in ZIP central-directory order. Determine the d02 member format from final-byte magic. For ELF64, traverse only SHT_SYMTAB sections in section-header order and their entries in entry order. For PE, traverse primary COFF symbol entries in raw table order, resolve long names through the COFF string table, skip auxiliary records, and include section-definition symbols. Discard empty names only; do not demangle or strip leading section prefixes such as .text$ or .rdata$. Submit the first exact remaining name matching /DiscoveryEngine.*score/. (typeinfo: /ZTI.*DiscoveryEngine/)

The four HELD ids were exactly the PE-shaped halves of that:

set2.d02_analysis_mangled_score_symbol   set2.d02_analysis_typeinfo_symbol
set4.d02_analysis_mangled_score_symbol   set4.d02_analysis_typeinfo_symbol

Sets 1/3/5 deliver d02 as an ELF64 C++ specimen; sets 2/4 rotate it to a MinGW-style PE. The adapter answered ELF from a raw-byte Itanium scan (correct, but by luck) and answered PE by guessing: it looked for a <section>$<name> string and offered [".text$...", "<bare>"] as two candidates. Two candidates is a probe, and the adapter never sends a probe - so those four ids were held rather than risked. That is the right call, and it is also the bug: the GM had stated a deterministic rule, so there was nothing to guess.

Fix - challenges/_lib/autosolve_binary.py

Implemented the GM's rule literally, so the fields answer SURE with no candidate list:

  • _coff_symbol_names(d) - walks the PE COFF symbol table from PointerToSymbolTable/NumberOfSymbols in the COFF header (e_lfanew+12, +16). 18-byte records in raw order; NumberOfAuxSymbols is byte 17 of each primary record and those naux following records are skipped; a name whose first four bytes are zero is resolved as an offset into the string table at PointerToSymbolTable + 18*NumberOfSymbols; empty names are dropped and nothing else is filtered (section-definition symbols stay in).
  • _symbol_table_names(d, k) - one ordered list per member: the existing elf() reader already yields SHT_SYMTAB sections in section-header order with entries in entry order, which is the GM's ELF rule verbatim; MZ goes to the COFF reader; anything else yields [].
  • _cpp_class_name(d) - the class the fields are about, read from the specimen's own _ZT[IVS]<len><ident> RTTI name, so the GM's regexes are rebuilt from the artifact instead of hardcoding DiscoveryEngine.
  • _cpp_symbol_field(d, k, kind) - first table entry matching <cls>.*score / ZTI.*<cls> / ZTV.*<cls>, returned as a single SURE answer. If the member carries no symbol table at all, it falls back to the old byte-scan + COMDAT route rather than failing.

Both dispatch sites now call it: the dNN_analysis_{mangled_score_symbol,typeinfo_symbol,vtable_symbol} schema and the older bare Day 2 mangled_score_symbol / vtable_symbol fields.

Why this is strictly better than the guess: in a MinGW PE the COMDAT section-definition symbols come first in raw table order, so the traversal naturally returns .text$_ZNK15DiscoveryEngine5scoreEPKc / .rdata$_ZTI15DiscoveryEngine - the Day 17 GM-proven PE spelling - while an ELF returns the bare _ZNK15DiscoveryEngine5scoreEPKc / _ZTI15DiscoveryEngine. Same code, both answers, no probe.

Mastery recovery (worth remembering)

The first mastery run submitted 860 accepted + 4 remaining and the server deadline (2026-10-18T13:04:48.998Z) then expired with unique_attempts_remaining = 0. That is not a dead mode: with the pool exhausted the GM offers next_op=practice, and the rerun correctly routed the one authorised timed write to op=practice instead of op=start (a start would only resume the dead attempt). Practice completed the mode with the full 864 fields. So a HELD-then-expired mastery is recoverable as long as the extractor is fixed before the rerun - and field_formats.confirm_all banked 4 new accepted tokens from it.

Lesson

When the GM spells out a traversal (table, order, what to skip, what not to strip), implement the traversal. A field that the question defines procedurally must never be answered by a byte scan plus a spelling guess: the guess becomes a probe, a probe is never sent, and the mode holds with the answer sitting one table walk away.
