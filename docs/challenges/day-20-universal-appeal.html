Universal Appeal (Day 20, metadata-forensics)

GM id: metadata-forensics-day-20-universal-appeal. Question: Determine macho.cpu_type_set for macos-001.bin (answer kind json: compact JSON array).

Single Solve - CORRECT

  • Flag: Token29f836971748707c3e26a94cab556c38
  • artifact_0.bin is a zip with one member, macos-001.bin (challenge artifact, not published) (56 bytes): a thin little-endian 64-bit Mach-O (cffaedfe), cputype bytes 0c000001 = 0x0100000c (arm64), one LC_UUID command.
  • Answer-format search (the GM never says the element spelling): bare 0x100000c wrong, ["arm64"] wrong, [16777228] wrong, ["ARM64"] wrong, ["0x0100000c"] CORRECT.
  • Accepted form: a compact JSON array of 8-digit lowercase hex strings with 0x prefix, unique CPU types in slice order, e.g. ["0x0100000c"] (fat files: ["0x0100000c","0x01000007"]).
  • Fix: challenges/_lib/hdr_facts.py now emits macho.cpu_type_set (thin and fat; fat uses each slice's own header cputype, falling back to the fat arch record).
