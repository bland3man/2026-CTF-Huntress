Challenge prompt

"The remote policy decoder is part of an access decision. A valid public decision is documented in the application; investigate what happens when that decision cannot be decoded."

There were no downloadable artifacts — each attempt assigned live target(s). SS and TT asked for one proof from a single target; MM asked for proof-1 through proof-5 from five independent targets.

Method summary

Single Solve + Time Trial (same shape)

  1. GET /api/clues on the assigned target. The response identified the feature route and documented the valid public decision shape: remote:<id>:<base64url-JSON> with a documented standard decision.
  2. Sending a MALFORMED value with the documented prefix (e.g. remote:40b12d94f983:not-base64!) to the feature route returned HTTP 200 with effect: "exceptional_condition_fail_open" and a proof_<hex> value.
  3. Submit that proof_<hex> under the exact answer_id returned by GM start (proof-1 in both SS and TT).

Lessons / faster-next-time

  • Each mode's targets are per-attempt. The route suffixes, session cookies, export IDs, and proof values change between assignments. Always use the current attempt's assigned URLs.
  • Follow visible clues first. /api/clues, robots.txt (not found in any source), linked index pages, and the public challenge prompt beat guessing paths.
  • Preserve session cookies. APIs that look standalone (/api/timeline, /api/cases/<id>) may require a home-page session cookie first.
  • For Mastery, inspect each target independently. Mastery can be a MIXED bundle of vuln types (archive leak, IDOR, SQLi, LFI, audit-event fail-open) — do not assume one exploit applies to all.
  • **Submit the exact answer_id from the start response** (proof-1 … proof-5 here, exact names only).
  • Don't guess answers; derive from live responses. The GM is never a value-probe.
