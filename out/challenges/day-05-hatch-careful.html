Peeling the carriers (the new layer)

Each *-recovered.py / source-context.py is INERT: imports only base64/io/os, has no sinks (the "reflective_name_plan"/"import" tokens are string literals in data tuples, not calls), and its only module-level code is a HUNTRESS_INSPECT_ONLY-guarded print. It carries:

  • MATERIAL_<h> : encoded descriptor bytes
  • CODEC_<h> : "representation|transform|key" recipe (documentation)
  • pure load/decode/recover/inspect_<h>() : decode descriptor text v=2|k=v|...
  • surface_<h>(): 4-tuple (syntax, obfuscation, carrier, windows_chain)
  • obfuscation_<h>(), plan_<h>(): operation-plan tuple (first elt = behavior verb)

The carrier "disguise" only varies HOW surface/obfuscation are computed (literal tuple, chr() join, format_map, reversed slice, string table, match/case) and HOW MATERIAL is encoded - the decoded descriptor always has the same keys. So the safe move is to exec the module in a throwaway namespace (guard never fires) and call only the pure inspect_<h>(), giving the descriptor kv directly. Every answer is then a dict lookup: adapter, campaign_id, syntax, obfuscation, carrier, windows_chain, and the indicator (host_id/file_path/url/upload_url/next_stage/extension/handoff_id).
